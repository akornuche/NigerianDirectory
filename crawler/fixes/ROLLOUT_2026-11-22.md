# Production rollout: remediation of 2026-11-22

Everything below was run first on the Neon branch `remediation` and checked
there. A full copy of production before any change is kept on the Neon branch
`pre-remediation-2026-11-21`.

## Why the order matters

The new API and frontend code query `verification_status` and publish only
records marked `verified`. If the code deploys before the database has the
column, sitemaps come back empty and API list endpoints fail. If it deploys
before records are marked verified, the site shows nothing. So: database first,
code second.

## Steps

1. **Schema** (additive, safe with the current code):
   `backend/database/migrations/008_add_verification_and_slug_aliases.sql`
2. **Universities** (corrections, verification against NUC):
   `crawler/fixes/2026-11-21_universities.sql`
3. **University content clean-up**:
   `crawler/fixes/2026-11-22_university_content_cleanup.sql`
4. **School verification** (strict; clears copied and unsourced content):
   `crawler/fixes/2026-11-22_school_verification.sql`
5. **School profiles** (original text from cited sources):
   `python crawler/fixes/gen_school_content_sql.py crawler/content/schools_2026-11-22.json > school_content.sql`
   then run `school_content.sql`.
6. **Deploy code**: merge the branch to `main`. Vercel deploys both projects.
7. **Verify** (see below).

Steps 2 to 5 are each one transaction; a failure rolls the whole file back.
Every file is idempotent and can be re-run.

Between step 4 and step 6 the current production code still lists
unverified schools, now without descriptions. Keep that window short.

## Verify after deploy

- `GET https://nigeriandirectory-api.vercel.app/health` returns `healthy`.
- `GET /api/schools?institution_category=school` returns only verified schools (56).
- `GET /api/schools?institution_category=university` lists 295.
- A retired duplicate's old URL 301s to the record that replaced it, e.g.
  `/education/universities/benue/makurdi/federal-university-of-agriculture-makurdi/`.
- A corrected record's old URL 301s to its new state, e.g. Rainbow College's
  `/education/schools/lagos/...` URL.
- `/sitemap.xml` and `/ai-sitemap.xml`: every URL returns 200.
- An unverified school's URL returns 404.
- `python crawler/audit/run_audit.py --sitemap https://www.nigeriandirectory.com.ng/sitemap.xml`
  with `DATABASE_URL` set reports no issues.

## Roll back

Point the frontend and API `DATABASE_URL` at a branch created from
`pre-remediation-2026-11-21` (Neon: create branch from that branch), and roll
the Vercel deployments back to the previous production deployment.
